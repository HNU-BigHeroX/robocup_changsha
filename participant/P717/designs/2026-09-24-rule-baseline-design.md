# P717 稳定规则基线设计

## 背景与目标

当前 `participant/P717/` 使用模板自带的 NumPy PPO 策略。本地公开预览的 8 个回合均能完成，审计拒绝数为 0，平均碰撞率为 0，但总分仅为 66.67。下一阶段将其替换为稳定、可解释、无需训练的规则策略。

本阶段的验收标准为：

- 公开预览 8/8 回合状态均为 `ok`；
- 官方预检查 `rejections=0`；
- 基础任务和协作任务的平均碰撞率均为 0；
- 策略运行不依赖模型权重或训练框架；
- 本地公开预览总分不低于 100。

以上结果仅表示本地公开预览结果，不作为官方最终成绩。

## 方案选择

采用“确定性目标分配加局部跟踪”的规则策略。与纯最近目标策略相比，该方案能减少多个机器人追逐同一目标的情况；与每步构造完整代价矩阵相比，它的状态更少、行为更容易解释，也更适合先建立可靠基线。

策略不得读取案例编号、评测种子、隐藏配置或官方评测器内部状态，也不得包含针对公开案例的坐标硬编码。

## 文件与组件

全部修改严格限制在 `participant/P717/`。

- `rule_policy.py`：实现 `RuleCoveragePolicy`，负责目标记忆、目标选择、追踪、避碰和边界保护。
- `entry.py`：只负责构造并返回 `RuleCoveragePolicy`，不再加载模型。
- `test_rule_policy.py`：使用标准库 `unittest` 测试规则策略。
- `submission.yaml`：将方法类型改为 `rule`，将 `train_command` 设为 `null`，并登记规则策略说明文件。
- `artifacts/README.txt`：说明该提交不使用模型。该文件只用于让 Git 和提交审计保留必需的 `artifacts/` 目录，运行时不读取。
- `LOG.md`、`experiments.csv`、`REPORT.md`、`THIRD_PARTY.md`：记录真实实现、依赖和每轮评测结果。

模板模型 `artifacts/policy.npz` 将被删除。`artifacts/README.txt` 的实际大小和 SHA-256 将在创建文件后写入 `checkpoint_manifest`。

## 策略状态与接口

`RuleCoveragePolicy` 实现官方 `Policy` 接口：

- `reset(context)`：保存机器人编号、机器人数量、目标数量、时间步长、地图范围、覆盖半径等公开上下文，并清空上一局的全部目标记忆。
- `act(observation)`：只根据当前合法观测和本局短期记忆生成二维动作。
- `close()`：不持有外部资源，因此为空操作。

每个策略实例只维护自己的状态，不使用模块级可变变量，也不与其他机器人实例共享记忆。

## 单步数据流

每次调用 `act()` 时按以下顺序执行：

1. 校验自身状态、队友和目标数组，只接受同时满足 `exists` 与 `visible` 掩码的观测项。
2. 将可见目标的相对坐标转换为绝对坐标，并用连续两帧位置估计目标速度。
3. 更新短期目标记忆；目标不可见时允许在固定 TTL 内进行短时预测，超过 TTL 后立即失效。
4. 根据确定性循环顺序选择目标：机器人首先负责 `agent_index % num_targets` 对应的目标，其余目标按照循环次序作为后备；同等优先级时选择距离更近者。
5. 生成目标追踪力。距离较远时朝目标加速，接近覆盖半径时逐渐减速，进入覆盖范围后制动并尽量停留。
6. 对过近的可见队友叠加排斥力，对接近地图边界的状态叠加向内修正力。
7. 没有有效目标时，根据机器人编号采用彼此分离的确定性搜索方向，并继续执行边界保护。
8. 对非有限数值执行安全回退，将结果逐分量裁剪到 `[-1, 1]`，返回形状为 `(2,)` 的 `float32` 数组。

所有控制系数集中定义并注明物理意义，后续每轮评测只调整一组通用参数。

## 异常与降级处理

- 自身状态缺失、形状错误或包含非有限值时返回零动作。
- 被掩码的全零行不得当作有效队友或目标。
- 目标短暂消失时使用短期记忆；记忆过期后切换到搜索，不无限追逐历史位置。
- 多个候选目标完全同分时使用目标索引稳定决胜，保证结果可复现。
- 最终动作出现非有限值时整步回退为零动作。
- 评测未达标时保留并记录真实结果，不加入按案例、种子或固定坐标区分的逻辑。

## 测试设计

单元测试至少覆盖：

- 动作的形状、类型、范围和有限性；
- `reset()` 清除跨局记忆；
- 对可见负责目标的追踪方向正确；
- 多个机器人在相同完整观测下具有不同的首选目标；
- 靠近可见队友时产生避碰趋势；
- 靠近地图边界时产生向内修正；
- 进入目标覆盖范围后减速或制动；
- 目标短暂消失时使用记忆，TTL 到期后转为搜索；
- 正确遵守 `exists` 和 `visible` 掩码；
- 空观测、异常形状和非有限值不会导致评测崩溃。

集成验证依次执行：

1. `test_rule_policy.py` 单元测试；
2. 官方提交预检查；
3. 全部公开评测；
4. 检查 8 个回合状态、拒绝数、碰撞率和总分；
5. 检查 Git 暂存区只包含 `participant/P717/`。

## 实施与记录流程

实现工作在 `P717-rule-baseline` 功能分支进行，采用测试驱动方式：先写失败测试，再实现最小策略，然后执行预检查和公开评测。

如果出现失败，按以下顺序处理：

- 单元测试失败：先修复策略逻辑，不进入公开评测；
- `rejections > 0`：先修复提交格式、依赖或审计问题；
- 碰撞率大于 0：优先调整避碰和制动，不以安全换分；
- 总分低于 100：依次检查目标分配、搜索、追踪和覆盖保持，每轮只调整一组通用参数；
- 经通用调参仍未达到目标：保留最佳真实结果，在报告中说明瓶颈，不声称已经达标。

每次正式评测结果都写入 `experiments.csv`，关键决策写入 `LOG.md`，最终方法、局限和最佳结果汇总到 `REPORT.md`。最终 PR 仅在组织方开放统一提交窗口后创建。
